Residual sign-off identity failure
==================================

reviewer_patch_check.py signed_off_by() uses git blame and returns only the
commit's free-form `author` name. accepted_by_designer() accepts every name
except those in REVIEWER_AUTHORS; there is no pinned designer allowlist and no
signature verification.

The reviewer process selected the designer's name locally without credentials
or a commit:

  git -c user.name=kaanow -c user.email=designer@example.invalid \
      var GIT_AUTHOR_IDENT

Output:

  kaanow <designer@example.invalid> 1785961952 -0700

The author value later returned by `git blame` is data supplied by the commit
creator. Any actor with write access can choose `kaanow`, `Mallory`, or any
other non-reviewer string; lines 184-189 reject only the literal reviewer
author. The current claim that a patch cannot accept itself is therefore not
mechanically established. An unsigned reviewer commit with a spoofed author
would be treated as designer acceptance.

Required identity boundary
==========================

Use a credential the reviewer does not possess. One concrete implementation:

1. Provision a distinct SSH signing key for the macOS designer and commit its
   public key/fingerprint as a pinned enforcement constant.
2. Have signed_off_by() locate the commit that introduced the exact acceptance
   line, then require `git verify-commit` to validate that commit against the
   pinned designer key. Author name/email may remain display metadata only.
3. Fail closed for unsigned commits, unknown keys, bad signatures, and reviewer
   signatures.
4. Poison with an unsigned self-signoff authored `kaanow` (must fail) and a
   genuinely designer-signed signoff (must pass).

If commit signing is unsuitable, use an equivalently independent approval
channel whose authenticated actor is not controlled by the reviewer, such as a
protected GitHub review/check written by a separate designer account. Merely
adding DESIGNER_AUTHORS would reduce accidental mistakes but would not prove
identity.
