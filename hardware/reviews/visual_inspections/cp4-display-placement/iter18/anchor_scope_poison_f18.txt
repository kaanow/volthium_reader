CLASS SWEEP — the same fall-through in other fields

F18 is "a field read by searching a whole balanced block falls through to a
DESCENDANT's copy when the real one is malformed". Every such read in
pcb/core.py was enumerated:

  ANCHORS — 4 sites searched the whole footprint chunk for `(at ...)`:
    _restore_properties        (footprint rotation)
    bodies_from_board
    refdes_boxes_from_board
    assert_refdes_roundtrip    <- the one F18 names
  All four now go through ONE owner, sexp_anchor(), which reads only a
  DIRECT child and returns None for a malformed one rather than falling
  back. (Single-owner, same reasoning that settled the back-side transform.)

  LAYER — 1 real instance found and fixed:
    _footprint_is_back() took the FIRST `(layer ...)` in the chunk. Every
    pad and graphic carries its own layer, so a missing or malformed
    footprint layer falls through to a descendant's — the F18 bug wearing a
    different field. Poisoned:
      well-formed FRONT fp with B.Cu pads          -> front  (both versions OK)
      well-formed BACK fp                          -> back   (both versions OK)
      MALFORMED top-level layer + B.Cu pad below   -> front  (OLD version WRONG)
      NO top-level layer + B.Cu pad below          -> front  (OLD version WRONG)

  PROPERTY "Reference" — 6 sites, assessed and deliberately left:
    a fall-through needs a NESTED `(property "Reference" ...)`, which KiCad
    footprints do not have (properties are direct children only). A missing
    top-level property simply fails to match and every caller already
    handles None. No fall-through path exists, so routing these would be
    churn without an invariant behind it.
